# Задание 1. Резервное копирование

## 1.1. Необходимо восстанавливать данные в полном объёме за предыдущий день

Для такого случая подходит полное резервное копирование, выполняемое один раз в сутки.

Суть подхода:
- создаётся полная копия всей базы данных;
- при сбое база восстанавливается из последней полной резервной копии;
- получается состояние БД на момент последнего бэкапа (например, за предыдущий день).

---

## 1.2. Необходимо восстанавливать данные за час до предполагаемой поломки

Подходит схема:
- полный бэкап + журналы транзакций (WAL);
- восстановление через PITR (Point-in-Time Recovery).

Позволяет:
- восстановить базу из полной копии;
- применить журналы изменений;
- вернуть состояние БД на нужный момент времени.

---

## 1.3.* Возможен ли кейс моментального переключения на рабочую БД

Да, возможен.

Используется:
- репликация (primary-replica);
- failover (автоматическое переключение).

Важно:
- это относится к отказоустойчивости;
- реплика не заменяет бэкап, так как ошибки могут реплицироваться.

# Задание 2. PostgreSQL

## 2.1. Пример команды резервирования и восстановления

Вариант 1 (plain SQL)

pg_dump -d mydb -f mydb.sql
psql -d mydb_restored -f mydb.sql

Вариант 2 (custom format)

pg_dump -Fc -d mydb -f mydb.dump
pg_restore -d mydb_restored mydb.dump

---

## 2.1.* Автоматизация

Да, возможно.

Используется:
- cron;
- systemd timers;
- Kubernetes CronJob;
- CI/CD (GitLab, Jenkins).

Пример:

0 2 * * * pg_dump -Fc -d mydb -f /backups/mydb_$(date +\%F).dump

# Задание 3. MySQL

## 3.1. Пример инкрементного резервного копирования

mysqlbackup --backup-dir=/backups/inc \
  --incremental --incremental-base=history:last_backup backup

Описание:
- --backup-dir - каталог;
- --incremental - инкрементный бэкап;
- --incremental-base - база для сравнения.

---

## 3.1.* Когда реплика лучше бэкапа

Преимущества реплики:

- высокая доступность (быстрое переключение);
- можно снимать бэкапы с реплики;
- масштабирование чтения;
- снижение нагрузки на основную БД.

Недостатки:

- ошибки и удаление данных реплицируются;
- не заменяет резервное копирование.
